## 锁屏强提醒回归

新增独立“日程强提醒”通知类别和无声原生前台服务。有限波形为 800 ms 振动、200 ms 间隔，最多 60 次；服务同时使用单调时钟截止时间和超时回调兜底。关闭、稍后、删除、改期和超时共用停止路径；页面重建、重复广播和新日程加入批次都不会重置截止时间。页面支持锁屏显示、点亮屏幕、长标题换行、倒计时，以及单项／批次按钮。设置页展示通知、任务振动、日程强振动、全屏提醒和准时提醒状态。

以上证明调度、通知、服务、页面和状态链路，不代表模拟器实际具备振动马达。覆盖安装到真机后，进入设置确认“日程强提醒”“锁屏弹出提醒”和“准时提醒”均可用；新建两分钟后的到点日程并锁屏，分别验证连续振动、60 秒自动停止、关闭、提前提醒及延后提醒。用户关闭振动或开启勿扰时，App 不绕过系统选择。

## vivo S9 / OriginOS 3 修复记录

用户反馈：亮屏有通知和振动，锁屏无通知、无振动。确认旧代码在 Android 14 以下点击“锁屏弹出提醒”没有任何行为，同时错误地把无需特殊全屏权限显示为“已允许”。现已补齐旧版本通知类别入口和不可用时的回退，增加通知高重要性检查，以及 vivo / iQOO 的后台弹出界面、自启动与后台耗电引导。厂商授权不能由公开 API 可靠读取，界面不会将其显示为已获准。

- Flutter analyze 无问题；18 项 Dart / Widget 测试通过，包括 vivo 的全屏设置、后台弹出与电池优化入口。
- 原生新增 Android 26～36 设置路由检查与全屏权限撤销／恢复检查。首次运行 15/16 通过，既有重复广播测试因服务异步刷新通知导致 postTime 相差 6 ms；改为检查批次、截止时间不变及唯一通知，重新运行 16/16 全部通过，包含真实系统闹钟锁屏唤醒用例。
- 后台设置使用公开系统入口，不假定 vivo 私有 Activity 名称；电池优化列表不是 vivo 后台耗电管理本身，应用内有手动路径说明。
- 本次未连接 vivo 真机，锁屏无通知的设备根因尚未由日志确认。需在 S9 完成自启动、允许后台耗电、锁屏／悬浮通知、后台弹出界面及准时提醒设置后复测两分钟后的日程，再测试长时间待机。
- Debug 与 Release 已用项目脚本顺序重新构建；Release 已同步到 `artifacts/TimeFlow-1.0.0-test.apk`。两种 APK 均通过 apksigner v2 签名校验，SHA-256 已更新。仍使用开发测试签名。本次未重跑 Flutter 集成场景与四页截图，上方对应记录保留自此前验证。

## 锁屏振动但不亮屏的后续修复

vivo S9 / OriginOS 3 用户确认已开启后台弹出界面、收到锁屏通知时亮屏提醒，但到点只有振动。此次调整通知投递链路：高重要性全屏通知不再兼任前台服务通知；前台服务使用独立低重要性、无声无振动状态类别，每个新批次重新发布全屏通知，同批次相同内容不重复通知。关闭／稍后／删除／超时取消活动通知。AlarmActivity 在 Manifest 声明 showWhenLocked 与 turnScreenOn，并处理 singleTop 的 onNewIntent 更新。

既有测试只查 dumpsys 中存在 AlarmActivity 记录，不能证明屏幕亮起。本次加强为：先确认屏幕处于非交互状态，再等待实际系统闹钟，断言屏幕已交互、当前批次提醒页已 resumed 且获得窗口焦点；连续执行两个独立批次，确认关闭后通知被清除。另检查弹窗通知不带前台服务标志、服务通知不带全屏 Intent，以及重复广播不重新发布通知。

Kotlin 编译和隔离模拟器原生回归已通过；Release APK 已重新构建并通过 `apksigner` v2 校验，SHA-256 已更新。通知拆分与前台服务主动启动页面是兼容性修复，尚无 vivo 真机日志证明该设备根因，需用新版 APK 真机复测；不会使用悬浮窗绕过系统权限。
